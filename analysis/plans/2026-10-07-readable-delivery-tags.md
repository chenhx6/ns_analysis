## 目标与规则

标签名称采用 `<Git提交作者>-<简短任务说明>`，例如 `chx6-启用自动提交与推送`。标签说明用中文写修改者、执行协作、依据、改动、成果和验证结论；不在名称或说明中填写 SHA256、完整提交 hash 或精确到秒的时间。Git 自身关联提交和内部验证摘要保留在 Git／本地元数据中。

同名任务在不同提交再次完成时使用短序号 `-2`、`-3`，不覆盖已有标签。新任务必须给出真实的成果说明，不能根据任务代号猜测成果。

现有六个自动标签逐项改为可读名称，保留原提交指向；先备份原标签对象、建立并验证新标签，再同步新名称并删除对应旧名称。仅处理下表明确列出的自动标签，不改分支或提交历史、不修改无关标签。

| 原任务对应内容 | 预计新标签 | 说明重点 |
| --- | --- | --- |
| 项目技能与运行环境安装 | `chx6-安装项目技能与运行环境` | 固定上游来源、项目内工具和可复现运行环境 |
| 重复技能清理及自动调用 | `chx6-清理重复技能并启用自动调用` | 删除冗余副本、集中路由规范 |
| 推送检查修正 | `chx6-修正交付标签的推送检查` | 只检查新发布历史，避免旧历史重复阻挡 |
| 解码调试文件与并发说明 | `chx6-保留解码调试文件并说明并行调度` | 保留原作者文件、澄清按 run 并行 |
| 自动提交与推送 | `chx6-启用验证后的自动提交与推送` | 验证、标签、指定远端和结束检查 |

历史未记录的执行协作者写“历史未记录”，不推定为 Codex。已知本会话的交付执行协作可如实写 Codex。

## 文件与方法

| 文件 | 操作 |
| --- | --- |
| `analysis/scripts/task_delivery.py` | 修改名称生成、中文说明、成果输入和准确标签收据；保留验证 tree／证据一致性检查 |
| `analysis/scripts/project_sync.py` | 接收成果／依据字段，从准确收据选择本次标签；不通过旧名称中的 hash 推断标签 |
| `analysis/scripts/test_project_sync.py` | 扩展实际本地仓库检查，覆盖中文标签、同名短序号、原成果说明和明确标签推送 |

## 验证与执行

1. 保存计划和程序；在临时仓库验证中文标签名、作者／依据／成果说明、同名任务序号、真实 tag 推送及禁止覆盖。
2. 核查六个旧标签的本地／远端对象和提交指向，冻结迁移清单；建立本地备份，先创建新标签。
3. 正常推送新标签并读取远端确认，再删除清单中的旧名称；删除前再次核对旧对象和替代提交一致。发生远端变化或新名称冲突时停止对应替换，不覆盖别人修改。
4. 更新规范与验证记录，自动提交／推送本次文件变更，生成一枚可读的新交付标签；核对工作区、远端分支及标签。

完成标准：已有标签列表可读、旧自动名称已替换，新标签指向原提交；当前新交付说明真实包含修改者、依据、改动和成果，名称和说明无机器校验字段；验证检查通过且同步成功。实际旧对象和回滚资料只保存于本地忽略元数据，公开报告不展开长 hash。
