# 程序留档、报告留存与回复约定修订

用户批准计划后，已同步主约定、计划模板、Ponytail 和 task-tag 两份技能、安装器及实际 hook 入口。程序留档按科学复现需要判断，报告按长期留存价值判断，回复必须能独立说明主要结果和重要限制。另按用户执行中补充，适配已移至根目录的 `run_log/`。

## 实际变化

| 情况 | 现在的要求 |
| --- | --- |
| 科学数据解析、筛选、变换、统计、拟合、模拟、导出和绘图 | 使用已保存、可复跑的程序，可复用已有实现；保留真实输入、参数、命令及验证。维护任务中的科学结果生产步骤同样适用。 |
| 查找、只读检查、问答、配置调整和工作流修复 | 可直接使用工具或修改现有实现，无需额外包装程序；实际代码和必要测试保留。 |
| 科学分析与图表、长期方法或决策、复杂证据调查、用户要求报告 | 保存报告，避免重复总结；新任务目录为 `analysis/YYYYMMDD-topic/`，报告放 reports。 |
| 普通问答、小修小改和临时检查 | 默认无叙述性报告；必要版本交付证据可单独保存为任务目录的 verification.json。 |
| 日常交付回复 | 给出主要结果、相关方法或改动、必要验证、重要限制和未完成事项；按相关性取舍，不设三行硬限制。报告用于深读，回复自身应能读懂。 |

日期采用 Asia/Shanghai 的任务开始日；跨日沿用原目录，既有任务原地续作。原始数据只读、Python 绘图、仅 SVG、最终渲染审查、先写执行计划和版本交付边界继续适用。
