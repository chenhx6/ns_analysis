# 技能目录清理与自动触发记录

## 清理计划

用户要求按任务自动调用适用技能与 hooks，删除根目录 `skills/` 的冗余副本，保留 `.agents/skills/` 和 OMX 使用的 `.codex/skills/`；其他冗余仅巡查汇报。

1. 编辑前逐文件 SHA256 比对三份技能树，确认 62 个入口、963 个文件完全一致，根副本没有独有修改。
2. 将项目约定、调用命令、来源清单和验证程序中的实际安装路径迁移到 `.agents/skills/`；上游来源路径与历史证据保留原义。
3. 用项目约定作为唯一自动路由规则源。允许技能隐式调用，共享包作为依赖加载；hooks 在相应事件自动执行，保留宿主权限、信任与用户暂停/取消边界。
4. 更新两个有效安装目录中的项目适配说明，并把必要的上游配置改动记录为项目覆盖，保留来源版本与原始校验值。
5. 再次确认剩余两份技能树完整、OMX 入口有效后删除根 `skills/`。验证不依赖旧目录，运行小范围 hooks/资源/调用检查。
6. 独立审计其余目录，区分运行依赖、来源快照、历史记录与可删除副本；不扩大本次删除范围。

## 行为保护基线

清理前实际比对通过：三份树逐字节一致；每份 62 个技能入口、963 个文件，根副本逻辑大小为 41,779,426 字节。保留 Codex 和 OMX 两种读取入口，保留全部技能支持资源、角色、提示词及原生 hooks。

`.runtime/` 中的执行副本用于数据盘兼容，属于有明确依据的兼容路径；本次不删除运行环境或改变该边界。root `skills/` 是可完全恢复、无独有内容的重复目录，属于本次明确删除对象。

## 完成结果与验证

- 根 `skills/` 已删除；62 个入口与完整支持资源在两个有效目录中保留。
- 项目引用与来源清单已迁移；上游 source_path 与历史记录仍保留原义。
- 报告/代码自动应用 Ponytail；语言处理和科研技能按需自动选择；全部技能的隐式调用策略开放，共享包按依赖读取。
- SessionStart/UserPromptSubmit hook 从 AGENTS 读取唯一自动规则。有效事件、错误输入、跨项目范围和失效资源均已验证。
- 一次只读语义检查覆盖科研报告、维护报告、双语论文/PPT、续作、数据声明；修正中文报告语言和引用原文的边界。另一次尝试的审阅代理因容量不足未启动，没有把它记作已通过检查。
- 清理后的完整离线功能验证 17 项通过，另有缺失/漂移资源负向测试和删除恢复性门。证据见 `skills_cleanup_verification.json` 与 `analysis/third_party/verification.json`。
- 其他冗余仅汇报，详见 `redundancy_audit.md`。宿主仍执行 hook 信任检查；没有伪造 CLI 登录、目标完成或模型调用证据。

推送门补充：新 annotated tag 可回溯远端已发布的旧布局，pre-push 现在结合目标远端已获取的 refs 只检查新发送历史。临时仓库回归确认旧布局不会误拦截，未发布数据即使随后删除及新建根 skills 副本仍被拒绝。

用户补充用途后，巡查报告撤回 `crate.dat`、`test.cc`、`run.sh` 的删除建议：前两项保留为原开发者调试文件，后一项保留为多进程解码调度底本。三项文件均未删除或修改。
